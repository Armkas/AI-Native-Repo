# Protected paths — enforced by scripts/guard-paths.sh (runtime pre-edit hook and CI).
# Format: <mode> <glob>   (glob is matched against the repo-relative path; * also matches /)
#   read-only    agents may never create, edit or delete matching files
#   append-only  agents may create new matching files but never edit or delete existing ones
#
# The CI layer cannot tell an agent's commit from a human's, so every rule here also applies to humans
# in pull requests. Protect only what nobody should change casually. A human who must change a protected
# file adds the `guardrail-override` label to the pull request (see .github/workflows/ai-guardrail.yml);
# the label is visible in review and needs repository write access.
#
# Adjust to your project. Examples:
append-only  db/migrations/*
append-only  supabase/migrations/*
read-only    .env
read-only    .env.*
#
# Lockfiles are regenerated by package managers through the shell, which pre-edit hooks never see, and
# legitimately change in every dependency update — protecting them would fail every such PR in CI.
# Dependency changes are an [Approval Required] action in MANUAL_TASKS.md instead.
# read-only    package-lock.json
